# 微信公众号关注列表自动开启工具（gzh_list_tool）

采集程序的**前置处理**：无论微信当前处于什么状态（收在托盘、主窗停在其他页面、公众号窗口开/没开），
运行一次 `open` 命令，都能把"公众号关注列表"独立窗口调出并保证其**处于显示状态**，供下游 UIA 采集使用。

- 语言/环境：Windows 10/11，Python 3.8+（实测 3.8.3 可用）
- 依赖：`pip install opencv-python pillow uiautomation`
- Python 3.8 环境注意：comtypes 需要 `pip install comtypes==1.2.0`（≥1.3 不支持 3.8）

---

## 一、命令

| 命令 | 用途 | 频率 |
|---|---|---|
| `python gzh_list_tool.py capture` | 截屏后框选"公众号"蓝色图标，生成匹配模板 `gzh_icon.png` | 换主题/换机器/阈值失灵时重做 |
| `python gzh_list_tool.py test` | 在当前屏幕找图标，打印得分与位置（弹图核对，不点击） | 模板变更后验证 |
| `python gzh_list_tool.py click` | 找到图标就真实点击 | 调试用 |
| `python gzh_list_tool.py open` | **完整前置流程**（见下） | 每次采集前 |

## 二、open 完整流程

```
1. 公众号独立窗口(标题"公众号")已存在?
   ├─ 是 → 激活它 → 点右上角人像(右上角-28,+56) → 关注列表显示 → 完成
   │       （这一步不依赖微信主窗，也不需要模板文件）
   └─ 否 ↓
2. 调出微信主窗(标题"微信"+Qt类):
   ├─ 主窗可见 → 前台化 + 点左侧聊天图标(30,110)，确保停在聊天列表视图
   └─ 主窗不可见(收在托盘) → 双击托盘隐藏图标里的"微信"唤出
       └─ 托盘没有微信图标 = 微信没登录 → 报错退出
3. 打开公众号独立窗口（双保险）:
   ├─ 路由1: 点搜索框 → 输入"公众号" → 回车（公众号会话顶到列表第一位）
   │         → 在(110,110)右键 → 点菜单第一项"独立窗口显示"(右键点+40,+20)
   └─ 路由2: 路由1未命中 → 聊天列表回顶 → 逐屏图标匹配(阈值0.97, 只扫最左220px列)
             → 找到后同款右键流程
4. 点公众号窗口右上角人像 → 出现新增的"微信+Chrome"窗口 = 关注列表已显示 → 完成
```

## 三、窗口识别规则（实测）

| 窗口 | 标题 | 类名 | 说明 |
|---|---|---|---|
| 微信主窗 | `微信` | `Qt51514QWindowIcon`（Qt 开头） | 可能藏在托盘（IsWindowVisible=False） |
| 公众号独立窗口 | `公众号` | — | 可独立于主窗存在 |
| 关注列表独立窗口 | `微信` | 含 `Chrome` | 与文章浏览页同款，只能靠"点击前后新增"区分 |

> 成功判据用"点击后**新增**的 Chrome 窗口"，因此文章页开着不会造成误判；
> 关注列表若本来就开着，点击人像不会关它（点击不是开关），校验走"已存在"分支。

## 四、可校准常量（脚本顶部）

| 常量 | 实测值 | 含义 |
|---|---|---|
| `THRESHOLD` | 0.97 | 图标匹配下限。真图标≈1.0，最近干扰项（服务号）≈0.919 |
| `MAX_SCREENS` | 15 | 图标扫描最大屏数（公众号实测会沉到 10+ 个会话以下） |
| `LIST_WIDTH` | 220 | 图标只出现在主窗最左 220px 列内 |
| `SCROLL_X` | 110 | 滚动聊天列表时鼠标的窗口 x 坐标 |
| `SEARCH_BOX` | (150, 57) | 搜索框中心（窗口坐标，下同） |
| `CHAT_ICON` | (30, 110) | 左侧"聊天"列表图标 |
| `SEARCH_ITEM` | (110, 110) | 搜索回车后公众号会话（列表第一位） |
| `MENU_ITEM_OFFSET` | (40, 20) | 右键菜单第一项相对右键点的偏移 |
| `AVATAR_OFFSET` | (-28, 56) | 公众号窗口右上角人像，相对窗口右上角 |

坐标均为**物理像素、以窗口左上角为原点**。脚本已做 `SetProcessDPIAware()`，高 DPI 屏幕下坐标自动一致；
但窗口尺寸/系统缩放/深浅色主题变化后，需要重新 `capture` 模板并复核各偏移。

## 五、集成到采集工程

方式 A（推荐）：把 `gzh_list_tool.py` 放进工程，采集前调用

```python
import gzh_list_tool

gzh_list_tool.cmd_open()   # 返回即代表关注列表已处于显示状态; 失败会 sys.exit 带原因
```

方式 B：子进程调用（隔离更好，便于超时控制）

```python
import subprocess, sys
r = subprocess.run([sys.executable, "gzh_list_tool.py", "open"], timeout=120)
if r.returncode != 0:
    raise RuntimeError("关注列表前置处理失败")
```

建议只在采集任务开头调用一次；采集过程中窗口被人工动过，下一轮采集自然会再修复。

## 六、注意事项（踩过的坑，勿回退）

1. **不要对微信窗口发 Esc**：主窗收到 Esc 会隐藏回托盘，后续全盘脱靶。
2. **不要用 ShowWindow 唤出托盘中的微信**：只会得到灰色空壳（渲染逻辑在微信自己的托盘点击处理里），
   必须走托盘图标双击。
3. **微信主窗 UI 对 UIA 几乎不可见**（整窗仅 1 个元素），聊天列表/搜索框等只能"前台化 + 模拟点击坐标"；
   关注列表本身是内嵌 Chromium，打开后 UIA 才可读——这正是本工具存在的原因。
4. **后台窗口会吞合成点击**：任何点击前必须把目标窗口切到前台（脚本内已用 ALT+SetForegroundWindow 处理）。
5. 强杀/重启微信不可取：重启后自动登录失效，卡在"需在手机上完成登录"，无人值守直接死。
6. 公众号聊天**不支持置顶**；聊天列表排序随消息变动，所以图标扫描要"回顶+逐屏"，或优先走搜索路由。
7. 模板匹配：图标出现未读红点遮角时会拉低得分，可把模板往图标内部缩几像素重截，或临时降阈值到 0.95。

## 七、诊断工具与产物

| 文件 | 说明 |
|---|---|
| `diag_tray.py` | 枚举任务栏托盘 UIA 控件名（托盘步骤失灵时先跑它） |
| `probe_scroll.py` | 实测聊天列表滚动距离、图标所在屏数与得分 |
| `menu_debug.png` / `search_debug.png` | 右键/搜索路由失败时自动保存的现场截图 |
| `found_screen.png` | 探针找到图标时的整屏截图 |

失败排查顺序：看 `open` 打印停在哪一步 → 对应窗口还在不在（`dump_windows` 输出）→ 现场截图 → 控件名/坐标是否因微信版本变化而漂移。
